# HSM — контекст мониторинга сенсоров

Контекст репозитория HSM (Hierarchical Sensor Monitoring). Существует параллельно с каноном `aicontext/glossary.md` в рамках триала навыков (см. `CLAUDE.md`, раздел Documentation Rules) — фиксирует термины, уточнённые в grilling-сессиях.

## Language

### Участники

**HSM-агент (Agent)**:
Автономный мониторинг-сервис на целевой машине (`hsm-agent.exe`, Windows; Linux probe), отправляющий данные сенсоров под access key продукта. Библиотека, встраиваемая в приложения, — это DataCollector, не агент.
_Avoid_: collector (для standalone-сервиса), «ИИ-агент» (другая сущность)

**ИИ-агент (оркестратор)**:
MCP-клиент (AI-ассистент), который провиженит ресурсы HSM через management API/MCP, а исполнение за пределами HSM берёт на себя своими средствами или поручает человеку.
_Avoid_: «агент» без уточнения в контексте, где возможна путаница с HSM-агентом

**Провижининг (Provisioning)**:
Часть процесса, которую делает сервер: привести ресурс HSM в нужное состояние по запросу через management API/MCP — например, создать продукт и выдать access key, принять адрес вебхука, выдать приглашение. Противопоставляется исполнению — установке на целевой машине или действиям в мессенджере, — которое всегда происходит за пределами HSM.

### Дерево

**Product (продукт)**:
Корневой узел дерева мониторинга, к которому привязываются access keys и HSM-агенты. Создатель продукта становится его автором (и менеджером по умолчанию).

### Креды

**Access Key**:
Пер-product-ный креденшел HSM-агента; сам ключ — это GUID, отправляемый в заголовке `Key`. Id ключа и есть секрет. Права — флаги `KeyPermissions` (CanSendSensorData, CanAddNodes, CanAddSensors, CanReadSensorData); состояние Active/Expired/Blocked.
_Avoid_: token, «ключ API»

**API Token**:
Персональный bearer-креденшел `hsm_pat_…` для `/api/v1` и MCP; зеркало прав владельца. Это НЕ то же, что access key агента.
_Avoid_: key, access key

### Установка

**Installer Bundle**:
Артефакт, который сервер генерирует по запросу: zip с подписанным `hsm-agent.exe` (Windows) или tar.gz с .deb (Linux probe) + `config.json` с адресом сервера и выбранным access key продукта + скрипты установки. Сервер генерирует и отдаёт бандл — сервер не является инсталлятором.
_Avoid_: «инсталлятор сервера», «голый .deb»

### Уведомления

**Чат уведомлений (Chat)**:
Адресат, куда уходят уведомления об алертах: одна запись может нести до трёх каналов доставки сразу — привязку Telegram, вебхук Slack и вебхук Mattermost. Чат без привязки к папкам доступа — глобальный (доступен для алертов отовсюду), с привязкой — только из своих папок; имя уникально на сервере (после #1829).
_Avoid_: «чат в Telegram», «группа» (это чаты в мессенджере, а не адресат в HSM)

**Креденшел бота (Bot credential)**:
Имя и токен единственного Telegram-бота сервера вместе с признаком «включён» — настройка уровня сервера, общая для всех чатов. Не то же, что привязка Telegram-чата.
_Avoid_: «настроить бота» без уточнения, «бот чата»

**Привязка Telegram-чата (Telegram binding)**:
Связь записи Chat с конкретным Telegram-чатом — личным диалогом с ботом или группой; создаётся только через приглашение.
_Avoid_: «подписка на бота», «регистрация бота»

**Приглашение (Invitation)**:
Одноразовая краткоживущая ссылка (для личного диалога) или команда (для группы), по которым человек в Telegram подтверждает привязку своего Telegram-чата к записи Chat. Согласие на привязку выражает действие человека в Telegram, а не запись на сервере.
_Avoid_: «токен привязки», «активация бота»

### Журнал

**Журнал (Journal)**:
Единый перечень изменений конфигурации — кто, когда и что поменял в дереве, алертах и папках, а после #1828 ещё в чатах уведомлений и настройках сервера. Часть записей можно откатить, остальные только посмотреть; значения секретов в записи не попадают.
_Avoid_: «лог» (журнал — про конфигурацию, лог — про события), «история изменений»
